# Local development and deployment

## Requirements

- Node.js 20.19+ (tested with 24), npm 10+
- Docker Desktop (for PostgreSQL)

## Local setup

```bash
npm install
cp .env.example .env              # then change POSTGRES_PASSWORD and DATABASE_URL
cp .env apps/api/.env             # the API and Prisma read apps/api/.env
npm run db:up                     # PostgreSQL 17 on 127.0.0.1:5432
npm run prisma:generate -w apps/api
npm run db:migrate
npm run db:seed                   # roles, default workflow, fictional staff
npm run dev                       # API on :3000, web on :5173
```

Open http://localhost:5173 → *Log in with Platonus* → choose a fictional identity on the mock login page.

Swagger UI: http://localhost:3000/api/docs

Everything runs locally: no real Platonus, NCALayer or government service is contacted.

> npm 11 blocks dependency install scripts by default. None are required for local development; Prisma's client is generated by `npm run prisma:generate -w apps/api`.

## Checks

```bash
npm run typecheck   # both apps
npm run lint
npm test            # API unit + e2e (needs PostgreSQL), web unit tests
npm run build
```

The API e2e tests create and drop a separate database `unidocs_test` on the same server; they are skipped automatically if PostgreSQL is not reachable.

## Production checklist

The API refuses to start in production unless the first four items are met.

- [ ] `AUTH_PROVIDER=platonus`, `STUDENT_DATA_PROVIDER=platonus`, `SIGNING_PROVIDER=official` — implemented and approved (see the integration docs)
- [ ] `COOKIE_SECURE=true`
- [ ] `VERIFICATION_BASE_URL=https://certificate.aheu.kz` (or the approved domain)
- [ ] `NODE_ENV=production` (also disables Swagger UI and the mock login)
- [ ] HTTPS everywhere; serve the web build (`apps/web/dist`) and proxy `/api` to the API on the **same origin**
- [ ] `TRUST_PROXY_HOPS` set to the number of reverse proxies
- [ ] Secrets (`DATABASE_URL`, Platonus credentials) from a secret store, never committed
- [ ] `STORAGE_DIR` on persistent, backed-up, access-restricted storage; PostgreSQL backups
- [ ] Do **not** run `npm run db:seed` (it creates fictional accounts and refuses to run in production)
- [ ] Provision the first SYSTEM_ADMIN directly in the database by an authorized operator, then provision staff through the admin dashboard
- [ ] Review the certificate wording in `apps/api/src/documents/pdf/certificate-texts.ts` and replace the logo placeholder with official branding

Example reverse proxy (nginx):

```nginx
server {
  listen 443 ssl http2;
  server_name certificate.aheu.kz;
  root /srv/unidocs/web;
  location /api/ { proxy_pass http://127.0.0.1:3000; proxy_set_header X-Forwarded-For $remote_addr; proxy_set_header X-Forwarded-Proto https; }
  location / { try_files $uri /index.html; }
}
```

Start the API with `npm run build -w apps/api && npm run db:migrate && npm start -w apps/api`.
